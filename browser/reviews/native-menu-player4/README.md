## API and ownership

- `preparePlayer(signal)` remains the existing P3 metadata-only API.
- `preparePlayer4(signal)` authenticates/caches original Repel metadata once under root lifetime and returns the ONE real P4 registry. Its `signal` equals root music lifetime; `resources` is the same object accepted by `createNativeRepelAudio`. Other consumers such as Repel must borrow this exact registry, never construct another.
- `prepareMenuPlayer(signal)` additionally authenticates/decodes SELECT through one persistent menu transport. Concurrent calls share work; successful preparation is cached for root lifetime. Caller cancellation abandons its wait, while bounded root configuration/sample preparation cannot publish a late action/voice. It never creates or unlocks audio. Technical locked/device failure remains diagnosed no-voice; missing/corrupt source configuration is explicit failure.
- `menuSE1500(owner, signal, {selectMuted:boolean})` dispatches synchronously after preparation. Native sound attr56 SELECT mute is REQUIRED and separate from global mute/volume/page visibility. SELECT mute skips allocation before preemption. Ordinary equal-priority attempts preempt before technical no-voice admission, as literal native PlaySE/SDK allocation does.
- `cancelMenuOwner(owner)` cancels only admissions owned by that caller. Old menu cleanup cannot stop another consumer's later P4 voice. Action abort, root abort and disposal remove owned nodes without changing shared gain/output.
- `anySEPlaying()` reads the actual existing P3/P4 registries live. `isSEPlayerPlaying(3|4|5|6)` exposes explicit queries; uncreated P5/P6 are Unsupported, not fabricated registries. No broader SE-player support is claimed.
- Existing P3 `diagnostics`, reporter semantics, failure policy and lazy admission remain unchanged. Separate optional `reportMenu` / `menuDiagnostics` contain menu status/failures. A menu reporting failure stops only its adapter's owned admissions; it cannot kill Root's native clock/P3 or dispose another consumer's P4 allocation. A later menu call observes that failure explicitly.

The existing single root `onAfterTasks` callback updates P3 THEN P4, even with no map scopes or `mapRunning=false`. There is no second clock, hook, Context, registry, RAF or sound timer. Natural finite PCM completion remains counted until that phase; native fade1 and priority behavior are inherited from the reviewed core. Root construction/teardown and partially failed P4 admission are tested without leaked listeners.

The production host must prepare the menu port before learner text/menu dispatch, then supply a synchronous SELECT callback and owned cleanup. Evolution's original556 session ABI intentionally handles only its five PLAYER3 SEs; SELECT is not mislabeled P3 or silently routed through it. Evolution glyph1 should borrow the real root any-SE query. All candidates remain within the parent battle audio ownership until the outer parent restores field music.

## Source proof and deliberate limits

Original SDAT authenticates SELECT1500 as PLAYER4, bank700, sequence volume54, channel priority104, player priority64; player capacity1, channel mask55296 (11/12/14/15), heap2000. WAV hash and all native INFO/SYMB/FAT/bank/SWAR/event payloads remain the exact accepted export. `test_repel_audio_resources.py` independently reads binary records, repeats the silent export, and compiles unchanged literal native PlaySE/player allocator/fader code with explicit device stubs. Current root integration tests additionally prove shared identity and P3-before-P4 phase composition. Deliberate copied-source controls prove those assertions fail on missing/reordered updates, duplicate registries/decode, omitted SELECT mute and leaking/Root-fatal paths.

This is a bounded browser PCM transport, not complete SSEQ execution or DS global16-channel allocation. SELECT's original track-end is6145 samples while the rendered finite release-tail is25776; browser onended→next soundUpdate is deliberate bounded behavior, not proven native ARM7 natural-end count parity. Existing accepted timing qualification and raw reviews remain under `native-repel-audio`. No parent/host/browser approval is transferred by dependency reuse.

Initial local integration tests had two fixture issues: incomplete original Azalea cue sets and an unawaited real switch completion during test teardown.
