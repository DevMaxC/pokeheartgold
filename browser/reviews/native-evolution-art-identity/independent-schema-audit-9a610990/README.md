The fallback `provenance.otId ?? Mon.id` in evolution-view 556 is invalid. This read-only audit pins clean campaign 9a610990 and the identical 556 view blob; 25 actual browser/native source files match the recorded commit bytes. No repository file was changed.

`createMon` receives only an OT name string. It draws six IV samples, a PID sample, and a separate instance-ID sample; the ID expression uses `rng()*0xffffffff`, while the true player profile comes from `newState`'s separate full-u32 `sampleUint32`. Ordinary creation supplies neither `form` nor provenance. The schema requires `id` but makes `form`, provenance and State.trainerId optional. Egg code explicitly calls `id` an instance token, uses PID as that token to avoid an extra draw, and stores true owner identity in provenance.otId. Hatch preserves the token while explicitly replacing real owner provenance. There is no authority to reinterpret the instance token as OT.

Actual caller coverage is in audit.json: starter; wild creation and capture; trainer parties; tutorial clone; Togepi gift/hatch; and explicitly unimplemented general gifts/trades. Ordinary capture changes only OT text then stores the same enemy object in party/PC; it does not repair OT/form metadata. Trainer creation overwrites PID/stats but leaves the unrelated ID. The native counterparts are distinct: starter/catch/memo use the real profile, trainer parties request random non-shiny OT and explicit packed form, NPC trades request preset OT/PID and named trade metadata. GiveMon has an explicit form argument. Thus one blanket current-player OT assignment would also be wrong.

The deterministic real-factory witness uses a separately known fresh profile 0x12345678, then rng=.5. It yields PID 0x80000000 and id 0x7fffffff; instance-based XOR is 0 and the old pure view rejects it as shiny. Actual profile/PID XOR is 50252 and the unchanged original C kernel classifies it non-shiny. Controlled identity-only art fixtures show that a true known OT overrides an arbitrary instance token and genuine known shininess still rejects. No partial provenance record is proposed by those function-port fixtures. The original C shiny macro/function was compiled unchanged with primitive fixed-width typedefs for 8 cases; this is not a full Mon/SDK or renderer test.

For true fresh data, store explicit default form 0, supported by ZeroBoxMonData/CreateBoxMon and the original 5-bit form field. Thread a known validated source-owner/preset OT identity from actual acquisition context; do not derive it from name, instance ID or a later current profile. Do not rewrite Mon.id or consume extra random draws for this purpose. The existing MonProvenance type requires a full real origin record: supply that only with true fields, or use a separately typed narrow OT identity field/port if only OT is known. Do not fake dates, map, language or ball merely to satisfy the type. If authorities coexist, validate consistency.

For old local browser saves, absence of provenance means **no native OT evidence**. Existing normal/base art can remain an explicitly declared browser presentation policy, without inventing OT or writing State. True known OT uses the native XOR; genuine shiny artwork remains unsupported until exported; malformed present provenance must not silently become the legacy case. State.trainerId cannot repair old acquisition identity: it is optional, and an older save may only acquire it lazily on a later Egg gift. Equal OT names prove nothing.

The logical evolution metadata port separately requires form. Fresh ordinary form 0 is a real source default. For missing old form, use an explicit one-time local-v2 base-form compatibility admission before queues/recovery checkpoints, minimally scoped to the already supported ordinary starter family. Retain explicit nonzero/malformed/foreign metadata as unsupported. This is a browser policy, not native form recovery; do not put `mon.form ?? 0` into each queue call. No OT synthesis belongs in that adapter. Native forms can be explicit for Shellos/Gastrodon, Pichu, trainer variants and gifts, so do not generalize the factory's default into all source callers.
