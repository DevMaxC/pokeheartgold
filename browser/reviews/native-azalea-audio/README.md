# Native Azalea sound leaf

This leaf supplies original SE1561 `SEQ_SE_DP_KI_GASYAN` and SE2171 `SEQ_SE_GS_ITOMARU_ROBO`, a shared native PLAYER3 registry, and the reviewed Azalea host's audio port. It does not install Main/World bindings, an audio clock, or a new AudioContext. No browser listening/GPU/gameplay, DS hardware/DAC, deployment, or full sound-engine equivalence is claimed.

## Original resources

`export_azalea_audio.py` reads `files/data/sound/gs_sound_data.sdat` directly, verifies SYMB→INFO→FAT identity and event payloads against independent ndspy parsing, and renders with the pinned DualRip commit `80f878b0ebf100f391028bcef69f7c5743473770`, ndspy4.2.0/numpy2.2.6. The manifest retains all source hashes, native sequence/bank/wave offsets and hashes, all695 native PLAYER3 SSEQ metadata records, and renderer code hashes. Source channelPriority89 is distinct from playerPriority64. Both cues use bank750, PLAYER3, whose native maximum is one sequence. Switch volume110 and robot volume120 are rendered once, with no extra browser gain multiplication.

The switch has20826 PCM frames at32768Hz. The robot has33458 frames, with native second-traversal loop `[16729,33458)` and a matching WAV `smpl` chunk. Native loop events, instruments, note/volume/pan/portamento/vibrato data and original wave samples feed the renderer; there is no synthetic composition or shader recolor equivalent. Repeating a rendered traversal is not live SSEQ execution. The DS hardware mixer, DAC, inter-sequence16-channel allocation, and platform output resampling are not emulated or verified here.

## Integration contract

1. Load metadata through `loadNativeAzaleaAudio(signal)`. Its generated SHA pins the complete manifest; every WAV is SHA checked before decode. Missing or corrupted source/configuration rejects explicitly.
2. Construct ONE `NativeSEPlayer3(resources, sharedPlayerLifetimeSignal)`. Every native PLAYER3 consumer must start through `player.play(id, owner, () => ({ended,stop}))`, including Cut1610 and hop1546/1606. Merely registering an already-playing sound cannot implement priority admission. Other consumers' actual source playback may be supplied, but this leaf exports audio assets only for1561/2171. Lower player priority rejects; equal priority preempts; native allocation precedes technical loading/admission failure. The global DS sequence/channel pool is outside this bounded registry.
3. Supply `createNativeAzaleaAudio(resources,{player,output,report,...})`. `output()` must borrow the existing `sharedAudioOutput()` result `{context,output,signal}`. The adapter never creates/resumes a Context, touches master gain, connects to `context.destination`, or disposes shared nodes. Source WAVs already contain their sequence volume. Borrowed owner identity is stable; the shared lifetime stops owned voices. Observe `audio.failure` for status/configuration callback failures, including asynchronous node completion.
4. Call `player.soundUpdate()` once at the actual shared field sound-update phase. Do not create a timer or competing field clock. Source `DoSoundUpdateFrame` calls `NNS_SndMain` after native main/task/vblank work. `StopSE(2171,1)` sets fade priority0, remains counted, then reaches zero and is force-stopped on the next sound update. A fabricated one-frame WebAudio linear ramp would differ from the original fader update. No Main phase binding exists in this leaf, so exact future combined phase timing is unapproved.
5. Host methods are `prepare([1561,2171],signal)`, `switch1561(signal)`, `robot2171(owner)`, `stop2171(owner,1)`. Missing source/ports reject. Technical decoder/start/device failures produce explicit `no-voice`; unavailable playback does not invent a delay or stop another higher-priority sequence. A switch with no voice still waits for any sequence on the same native player. Each owner only cancels its own current voice. Context suspension/closure ends owned transport and reports no-voice; disposal/abort drains owned nodes and bounded reads/decode observers. A late noncooperative decoder cannot publish a voice.
6. `audio.isPlayerIdle(1561)` exposes the live entire-player condition. **The frozen original host uses a completion Promise, which can latch an idle interval before another sequence starts before its next script poll. A separately reviewed host follow-up must sample this live port on EVERY scripts-phase poll. This known boundary is not claimed fixed by this audio-only source commit.** Parent has authorized that follow-up. Future Main must register all PLAYER3 consumers, bind the one sound-update phase, observe failures and shared lifetime, and review the resulting combined bytes.

`dispose()` destroys this adapter's buffers/nodes/owned playback only. Global player disposal belongs to the shared owner, not a map-local Azalea action. Master mute/preferences remain the borrowed gain; sound playback is not silently bypassed because a gain happens to be zero.
