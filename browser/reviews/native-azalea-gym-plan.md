# Native Azalea Gym topology and movement plan

This is an isolated pure data/state/planning layer. It makes no VM, main, World, UI, terrain, music or saved State-union change. The Gym remains unplayable until its original model, route/track animation poses and awaited player/follower hosts are integrated and reviewed.

`export_azalea_gym.py` imports all eight authored C polylines, twelve logical station positions and48 station/switch slots from `src/field/gymmick/azalea.c`.36 slots are usable;12 are genuinely empty and must not receive an invented route. Initial saved spider positions are[0,1,2,7], switches0 (`gymmick_init.c`). Switch0 toggles bit0 and source track models116/117; switch1 toggles bit1 and115/122. The initial trace undercounted the polylines as seven;8→11 is the eighth and is exported/tested.

`initialAzaleaGymState`, `azaleaGymEntryState`, `flipAzaleaGymSwitch` and `planAzaleaGymRide` do not mutate their input. Ordinary Continue copies retained stations/switches. Both connection and real-warp entries run the actual Azalea OnTransition script (`0642` binds `_016`, whose first command is `AzaleaGymInit`) and return native initial state. Connections are not naturally available in this indoor map; they still follow the native lifecycle. Invalid/duplicate station records reject. A ride requires an actual owned spider at the requested station and an existing slot. Reverse stations3/4/5/9/10/11 reverse the source polyline and assign player Z offset1/follower0; forward assigns player0/follower1. `completeAzaleaGymRide` rejects stale switch/station snapshots and commits only the relevant spider destination. Native does this at the final movement endpoint, before docking/shake/disembark; a parent action checkpoint must restore it if later presentation fails.

The SDK fixed-point functions are present in this repository. The planner ports `VEC_Normalize`'s integer division, integer square root and signed rounding with BigInt, followed by the source2-native-unit step. Case5's independent X/Z overshoot checks freeze an overshooting component until both axes can snap to the endpoint. This retains native diagonal tick counts rather than using an idealized Euclidean tween. Separate Python SDK replay produces all sixteen directed-polyline fixtures; all36 usable plans match their segment velocities, ticks and sampled fixed-point poses. First cart0→4 takes209 movement ticks at30 ordinary field ticks/sec, with segment ticks16/48/16/49/24/48/8; the reverse also takes209.

`azaleaGymRideFrame(plan,tick)` returns literal model/player/follower poses in tile units. The model has X center+0.5 and integral sourceZ; both riders have X+0.5/Z+0.5 plus their opposing0/1 offsets, Y0. Boarding advances one native step toward the model; disembarking advances another in the same direction after the ride. Neither can be replaced by a hidden teleport. They are host movement operations, not included in `movementTicks`.

Authored postincrement waits are five ticks for `counter++ >= 4` and nine for`>=8`, with one docking state tick and seven shake ticks. Four alternating1-native-unit camera deltas occur on shake ticks1/3/5/7, finishing with zero cumulative offset. The helper returns these small offsets without resetting a user's orbit. Follower wait, boarding/disembark movement completion, original model animation and sound completion remain external; there is no fabricated fixed total duration for the entire interaction.
