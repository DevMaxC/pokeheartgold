# Native action-end processing after recoil

Base: `2e85fc26f5af3addaf2ccb5a6e121837b4823b7a`. The base includes the separate fix for native effective speed zero. This change modifies only `battle.ts`, adds `battle-action-end.test.ts`, and records review evidence. Main, World, hatching and source assets are unchanged.

The earlier actual Opus review of `b30324e` found two LOW defects. Its historical verdict remains attached to that revision. The speed clamp was corrected in the base; this patch addresses the surviving actor whose opponent faints from recoil. The former symmetric HP condition skipped that actor's entire action, including self moves, status checks and PP use.

Native `battle_controller_player.c:3329–3334` grants EXP and checks battle outcome after each action. A usable bench allows the next living actor's action to continue. `FightInput:1698–1706` reads the current selected move slot and resolves its target again: a move learned during the intervening EXP task can replace the originally selected slot. Earlier action priority remains the priority used when execution order was selected. The browser now settles action-end faints/EXP/outcome after each Fight action and retains the selected slot index for the next actor. New sendouts still wait until residual effects finish.

`BattleSystem_GetMoveTarget` in `battle_util.c:1419–1438` maps native ranges SPECIAL=1, USER=16, USER_SIDE=32, FIELD=64, ALLY=256 and SINGLE_TARGET_USER_SIDE=512 to the actor in single battles. Those values come from `include/constants/moves.h:493–504`. Opponent-target moves have no target if the opposing active mon is already fainted. Native `TryMove:2654,2685,2691` checks status, deducts PP, and then invokes the no-target script. The browser preserves that order and emits the literal `messages/197.json:1234`, “But there was no target...”, before accuracy/effect/damage work. Source `subscript_0281_NoTarget.s` is the reference. Supported self/user-side/field effects continue without damaging the fainted opponent. Unsupported move effects retain explicit failure behavior whenever the effect would actually run. A proven no-target action bypasses effect preflight, spends PP and returns before effect execution. Live-opponent ranges0/2/4/8 use the literal native filtering. OPPONENT_SIDE128 remains a valid side target when its active mon fainted. FRONT1024 uses normal dead-opponent filtering unless the selected move slot changed during EXP; then native FightInput retargeting retains an opposing battler ID. The original selected ID is threaded internally to distinguish these cases. This does not implement Me First or any unsupported effect.

Public `Battle.start` fixtures cover both recoil directions, bench versus final outcomes, Harden/Recover/Haze, opponent-target PP and native no-target text, sleep/wake/paralysis ordering, no EXP/EV for a recoil-fainted participant, living Exp. Share payout and an unchanged real gifted Egg. A literal imported Porygon fixture starts at level17 just below18 with selected Tackle and four known moves. A faster Rattata's Struggle recoil causes its faint, EXP raises Porygon to18, and native Recover replaces the selected Tackle slot. The surviving player then executes Recover with the new HP/stats and spends its PP before the next enemy arrives. The final-enemy variant completes EXP/learning but never spends a second action's PP. These are mechanics fixtures using original data, not a claimed native ROM playthrough.

Eight focused fixtures fail five relevant assertions on the pre-F2 base (self move PP/effects, both directions of no-target PP, sleep countdown and learned move PP), while three final-stop/recoil/Egg checks already pass. The final candidate passes all108 battle/early-effects/Egg-consumer checks (86 top-level plus22 source-owned subcases) and TypeScript. A second actual review found that an unsupported opponent effect must still take the native no-target path because its effect never runs. Three additional regressions fail on that first candidate and pass after the correction. No build or rendered-browser check was run here.

Existing gaps remain explicit: broader target/effect systems, native global RNG draw sequence, wider speed/EV ability and held-item modifiers, Trick Room, doubles, trade acquisition and simultaneous-last-KO Draw policy. This patch does not certify hatching, full battle parity or rendered 3D behavior. The existing full-moveset replacement UI does not emit every native learning message; the selected-slot fixture verifies actual move/state behavior rather than claiming complete message parity.

Additional fixtures use the real Cyndaquil18→19 Flame Wheel learnset and a surviving foe with Flame Wheel to prove unsupported opponent effects can finish no-target handling without running. Living Flame Wheel, Reflect, Sunny Day and Spikes negative controls prevent a blanket unsupported-effect bypass.
