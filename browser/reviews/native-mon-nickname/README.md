This leaf supplies nickname metadata before native evolution admission. It does not wire Main, change the VM, run the naming UI, or enable evolution. The base is immutable `41493524d78b6d62ff5b0a3656bb1fcce0bee985`; its accepted evolution predicate is unchanged.

`mon-nickname.ts` owns the original English canonical name, exact stored-glyph comparison, naming `noInput` result, and an explicitly separate old browser-save policy. `data.ts` gives newly created ordinary Pokémon their pinned canonical name and `hasNickname:false`. Original assets/data are unchanged. `nickname-data.ts` is reproduced by `python3 browser/scripts/export_nickname_data.py --check` from original bank237, charmap, constants and source hashes. All496 rows match the existing names export; national species names use33 distinct glyphs. The encoder retains2870 unique single-scalar glyphs and rejects the ambiguous fullwidth `ｚ`, unmapped/compound/control encodings and input longer than10 glyphs. This is storage encoding, not a claim that the English naming keyboard admits every encoded character.

Original behavior is literal: `ZeroBoxMonData` clears the flag, `CreateBoxMon` sets the species default, and plain `MON_DATA_SPECIES_NAME` only copies text. `MON_DATA_NICKNAME_FLAT_COMPARE` (attribute118) / `STRING_AND_FLAG` (120) compare the submitted native u16 string against message237 using `StringNotEqual`, then copy. There is no trim, case fold, punctuation alias or Unicode normalization. `NamingScreenApp_Exit` treats empty/all-native-CHAR_SPACE input as no input. CHAR_SPACE478 represents ASCII space; U3000/native1 does not count as blank. Field `Task_NamingScreen` separately compares the submitted name with the current/default name; unchanged means no input and preserves the existing flag. Native NPC trades can deliberately force the flag true even for canonical-looking text, so no-input never recomputes a present flag. Capture and hatch create a blank naming buffer and use their own result flow; they must not inherit the field-only unchanged-current-name rule.

`ScrCmd_NicknameInput` passes a result-variable pointer through the field task. For Pokémon naming, 0 means an applied name and1 means no input. Result2 belongs to duplicate group naming, not this command. This leaf returns the exact `0|1` type. Unsupported subject/data/input throws before a named write. No-input leaves both name and flag untouched, including an absent legacy flag. It does not manufacture a void/undefined return fallback.

The compiled oracle extracts the unmodified original FLAT_COMPARE case, `StringNotEqual`, all-native-space function and field equality fragment. Source name storage and equality-only `String_Compare` are bounded stubs; primitive headers/one original length macro are supplied without the full SDK. It is not a full encrypted-Mon or naming-screen emulator. The23,480 cases cover493 national species, both incoming flags, field/capture modes, exact/case/custom/leading/trailing/all-space/empty/U3000 input and unchanged custom text. Tests also replay the historical exact Main handler, whose text-only assignment demonstrably leaves a false flag and returns undefined. That control is not a claim that Main is fixed.

The migration is an explicit **browser-local version2 compatibility policy**, not reconstruction of a raw DS nickname flag. Call `migrateLegacyBrowserNicknames(data,state,{origin:'local-browser-v2'})` once on admitted old local saves before queue admission. Exact current canonical text with no flag becomes false, so ordinary old default starters remain supported. Every other existing text becomes true and is preserved byte-for-byte, including TitleCase legacy defaults and arbitrary old Unicode. Present booleans are authoritative and retained. Eggs are skipped; corrupt/invalid records, foreign-language missing flags and unavailable original canonical rows remain explicit unresolved entries. A partial receipt does not admit an unresolved Pokémon to evolution. The strict queue must still require a boolean for the actual slot; it must not infer on every call. No save version bump or live-save modification is performed here. A repeated call changes no already migrated flag, but Main should retain/persist the first migration receipt at its admission boundary rather than using this as a recurring predicate.

The factory and later naming bindings must ship together before live evolution: applying factory-false while retaining Main's old text-only setters would mislabel newly custom-named Pokémon. [The binding plan](BINDINGS.md) records the exact remaining work. Existing UI trims, truncates and requires nonblank input, accepts a broader browser charset and cannot produce every original noInput case. Those keyboard/UI and name-rater gaps remain partial. No full naming, all-language, all-game, browser or campaign approval is claimed.
