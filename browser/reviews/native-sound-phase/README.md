# Shared post-task sound phase

This isolated leaf is based on campaign354223cb. It changes the shared clock and field music ownership API, without Main/World or actor edits. Native Azalea host/audio/renderer bytes from704cacea are frozen and are not changed here.

`NativeFieldClock.onAfterTasks(callback, rootSignal)` registers a synchronous global callback in stable order. It runs once per admitted existing30Hz field tick, even without field scopes and when mapRunning=false. A second actual MessageChannel task boundary drains runnable task-completion Promise jobs before `phase='after-tasks'`. A final task can therefore request native StopSE(fade1) before the shared PLAYER3 sound update. This is not a new timer/RAF or a guessed Promise-flush count. Pending noncooperative I/O is not declared drained.

Map transitions retain that global phase/hook and cancel field scopes with their exact original reasons. Local controller cancellation affects only its scope. Final clock dispose/fatal aborts the phase and removes hooks. The hook's explicit owner abort removes it without disposing another controller or global registry. Callback errors are fatal/observable via clock.failure, including after a field-generation change. Callbacks must be synchronous; registration during tasks/after-tasks rejects explicitly. An owner signal and final clock disposal prevent a late boundary completion from writing.

`player.lifetimeSignal` is a stable readonly getter available before unlock/Context creation and after disposal; it is the same signal later returned by sharedAudioOutput. Reading it does not allocate, resume, download or change gain. Root can construct one native registry and register its sound callback before unlock, and shared player disposal aborts both via that signal. Map transitions must not dispose that root registry.

## Literal native cadence and limits

`src/main.c` ordinary NitroMain executes TaskManager/overlay work, main SysTasks, print/vblank work, then exactly one DoSoundUpdateFrame. `src/sound.c` calls NNS_SndMain there. `src/system.c` increments frameCounter on VBlank; ordinary fast offline iterations have two VBlank waits, with the first skipped only if VBlank already elapsed. `Comm_Update` in communication_core.c unconditionally returns TRUE; there is no demonstrated Comm-skipped field path in this source. The current clock's admitted30Hz/stall behavior is retained. Variable native workload/hardware/VBlank timing is not continuously emulated. The communication-error/reset loop separately calls sound update per WaitForVBlank; this leaf does not claim that non-field path or global60Hz parity, nor introduce a second clock to guess it.

The source C oracle compiles actual SDK StopSeq/fader/PlayerMain/count bodies with explicit hardware/list stubs. It proves that fade1 retains priority0/count until the next PlayerMain, idle updates do not double-stop, natural completion retires there, and fade0 is immediate. It is not hardware/DAC/full scheduler emulation. The exact reviewed native registry is copied as a test-only byte-pinned dependency under frozen-azalea-dependency; it is not a new runtime copy or a change to its accepted source.

The Node tests include a real early-onTick negative counterexample and current final-frame fade positive, no-scopes/global phase, cancellation reasons, local failures, disposal/owner abort at either boundary, pre-unlock lifetime ownership, no catch-up, registration guards and fatal-after-cancel behavior. `check_native_sound_phase_before.py` uses the exact original7202dc98 clock with API-only observation instrumentation; it retains the old empty-scope early exit and map-boundary abort. Both new global-hook expectations FAIL there. Its diff is preserved so this is not mistaken for a shipped original API. Private compatibility overlays enable a no-op global hook in held Azalea28 and campaign Cut13 fixtures; no held runtime is edited. An initial Cut private fixture lacked the original src/scrcmd_sound.c file and is retained as incomplete fixture evidence, not a runtime failure.
