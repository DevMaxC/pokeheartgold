# Mom savings backend integration contract

Frozen leaf module is based on5c39d05d32b56aa5aeb848d61f4c6e089299b1ce. It adds no main/UI/World/types bindings. Host integration is a separate reviewed change.

1. At ordinary battle setup capture `beforeMoney=state.money` and `sentToMomMessage=momSavingsActive(state)`. Native battle_setup.c242 snapshots the flag plus bank<999999; this display flag can be true even when the actual later deposit is zero. Do not recompute it after purchases.
2. Calculate the existing supported prize/loss into the capped battle-profile wallet (0..999999). The native winning message uses nominal prize and the captured message flag, not the eventual transferred amount. Pay attention to wallet cap: quartering nominal prize is wrong.
3. At native result-copy timing, after battle prize/loss presentation and before ordinary overworld resume/WhiteOut, call `settleMomBattleMoney(data,state,{beforeMoney,afterMoney,random16})` once for every ordinary committed battle result, including zero gain/loss. This routine also checks already-eligible normal gifts, so do not skip it merely because no prize, Mom display flag false, or deposit zero.
4. Supply an explicit raw unsigned16-bit RNG draw for the berry branch. The core consumes none for normal gifts/full queue/no tier crossing and exactly one `draw%17` for a qualifying berry event. No browser-global LCG seed stream is invented by this helper. If the draw port owns mutable seed state, its rollback belongs to the outer checkpoint.
5. The synchronous helper commits wallet, packed FIFO queue (at most5), bank, normal-gift bit mask and pending phone bit12. If the returned fresh `phoneTrigger` is nonnull, call the field manager's `triggerQueued(12,true)` after the bit is committed. Do this for every fresh purchase batch even if bit12 was already set. Loading saved bits/queue on Continue must not synthesize an acceleration event.
6. Include both State and FieldPhoneHost snapshot in the existing OUTER source-action transaction; failures in later presentation/quest/phone work must restore both. Do not save a provisional trainer battle separately from its containing source script. The unit fixture exercises actual SourceActionRecovery and FieldPhoneHost for this contract, but it is not an actual-main integration test.
7. Older absent/partial stores default only missing bank/mask/queue fields to nativezero. No historical deposits/purchases/refunds are inferred. JSON save/reload naturally preserves the new optional store. Provided invalid values are rejected rather than silently destroying funds. Mother saving No toggles the policy flag without clearing existing funds/gifts/pending calls.

Remaining explicit gaps: main has not been wired; incoming Mother gift calls are still unsupported by current FieldPhoneHost; source deliveryman/gift Peek/Pop, bank transfer UI and ordinary Mother phone presentation are unported. Queued item IDs/quantities are persisted for future source delivery, and do not enter the bag automatically. This leaf does not claim complete Mother, native global RNG, trainer prize modifiers, or full battle parity.
