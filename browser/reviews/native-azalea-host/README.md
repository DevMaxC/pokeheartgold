# Azalea field and VM boundary

This leaf connects the reviewed original Azalea renderer to source script commands, completed field coordinates and an injected shared native field clock. It does **not** change Main, UI, battle or the audio player. The controller is not installed by current Main. Those binding points, actual sound transport admission and combined browser validation remain required before calling this a playable production integration.

The renderer/resource leaf is unchanged: `gym-azalea-world.ts` SHA256 `f102ac4d8b1282bae81d699c2bf9005172c123155325b4e03b20958d1c309d46`. Its original reviews and limited rendering/SDK scope remain separate. This host does not use its default RAF clock. Original model buffers, textures, native pose tables and resources are not changed here.

## Source behavior

`src/scrcmd_c.c` reads the station/switch as literal bytes. Actual script0869 entries002–013 request stations0–11,014/015 request switches0/1,016 initializes the gym. The host checks actual map180/key `MAP_AZALEA_GYM` and the VM's abort signal. Missing ports stop explicitly. All twelve original NULL route slots remain errors; no cart is spawned or teleported to an unoccupied station.

`src/field/gymmick/azalea.c` supplies the four saved carts, source2-unit/30Hz route movement, follower wait, up/down boarding/disembark, movement73/74, five waiting ticks, one docking tick, seven camera-shake ticks and nine waiting ticks. Eight2-unit walking ticks move each rider one16-unit tile. Those actor steps have an explicit adapter animation override; this is not a port of the whole DS map-object animation scheduler. The renderer maintains exact route arithmetic and native model/PAT poses. The host keeps source logical current tile centers in `State.x/z` while a separate position-vector override carries the route. `MapObject_StartWalkMovement` changes current coords at the first walking tick; movement records expose that destination and the retained previous point, and `settle` updates previous coords after the eighth offset. During the spider route itself only position vectors move until docking. At the last route tick the spider save commits; the following docking tick updates current and previous actor coordinates through `settle`. Disembarking performs the same native logical-target/vector split. Its readiness is returned through the next scripts-phase TaskManager child-completion poll; parent bytecode resumes in that same tick, without a SetupNativeScript-style extra bytecode tick. The original global MapObject/SysTask insertion order is not emulated by this bounded host.

Ordinary Continue retains the saved spider/switch state. Native OnTransition initializes on warp and connection; connections are not naturally available in this indoor matrix. The actual `AzaleaGymInit` command always resets, including if explicitly executed after Continue (`src/gymmick_init.c`); Continue preserves state by bypassing that command. Warp/connection discard stale malformed puzzle data before decoding it. The World entry call accepts an explicit seventh `'continue' | 'connection' | 'warp'` argument, defaulting to warp. Source recovery must use Continue hydration after rolling State back; it must not rerun source entry scripts.

One persistent `NativeFieldClock` owns World.fieldTasks. The map scope advances static native poses; one synchronous callback also advances each action's owned phase job. Separate action scopes wait/dispatch without installing callbacks during task execution. A resource admission awaits the actual current clock phase before registering its callback. The shared clock is a30Hz script→real-task-boundary→owned-task host; it is not a complete emulator of DS task priorities/insertion or GPU packet scheduling. Stalls slow it rather than bursting catch-up ticks.

Local cancellation aborts only Azalea's action, drains its renderer finally/rollback and preserves other controllers' scopes. A real transition releases riders/shake before globally cancelling the clock. Same-map failure restores completed rider/puzzle checkpoints; unload does not restore departed actor positions. Every forward actor write checks the live owner, map, signal and stable actor identity before and after the port. Cleanup releases only the host's movement override and never updates actor positions/facing.

World skips static managed models115/116/117/122 only when an Azalea host is installed and the actual map key matches. The dedicated renderer admits all six original placements and four original118 carts. Other maps and a hostless World retain their native static props. Source permissions/BDHC and ordinary walking collision are unchanged; this forced source ride bypasses normal walking, while VM.busy and the Main action lock prevent player input.

Camera shake offsets both camera and look-at by the same cumulative Z delta; it does not reset yaw, pitch or distance. Native forget/track intervals freeze/resume streaming using the actual rider vector. The camera still follows the route. This does not create a second camera object or take over scripted camera241.

## Required Main binding

1. Construct/attach the shared `NativeFieldClock` once, independently of Cut actor admission, with actual World field/running/error ports. Construct `AzaleaGymHost(world,state,clock,ports)` before entering map180. Its constructor installs `world.azaleaGym`; disposal releases it and its resource cache.
2. Bind `vm.hooks.azaleaGym = host.scriptPorts`. Retain this binding when recreating the VM during recovery. Pass the explicit seventh entry kind to World.enter. In restoreField pass `'continue'` after restoring State and before actor hydration; existing six-argument Violet hydration is insufficient for Azalea.
3. Supply stable, host-owned player/follower actor records with `position`, `facing`, `place`, `settle`, `face`, `movement`. Cache their identities rather than constructing new records per getter. `place` updates the actual actor vector. `settle` updates current/previous logical coordinates and clears the relevant tween/followerPrevious/followerMoving state. Host State coordinates are source logical centers and must not be overwritten by render interpolation. Movement records carry `current` and `previous`; the follower adapter retains those independently of its visible vector. A changed actor identity cancels an action.
4. During render prefer the **full** `host.riderPosition` vector over State/tween/terrain position for the player. Honor owned movement overrides and `playerHeld` before normal sprite animation. Follower vector/animation writes similarly honor its host-owned record. `movement(null)` only clears this host's override even after map unload; it must not change coordinates/facing or release another owner's movement. Cleanup ports must be idempotent.
5. Keep user movement/menu admission locked while the VM/action/host is moving. Do not globally block World.walkable or ambient NPC movement. World streaming and camera already consume the host's actual/frozen vector, preserving orbit.
6. Supply **actual native sound** ports: prepare source SE1561 and2171 configuration/assets before any rider/switch mutation; await actual1561 completion; start2171 with an owner token; stop that same token with native fade1. Native PlaySE ignores admission failure: a technical device/context/voice failure returns a diagnosed `no-voice` outcome and allows visual/script progression. A missing source asset/configuration/host remains an explicit prepare error. The host records these outcomes and polls switch completion at native task boundaries, with at least one poll even for no-voice. Ports must return `voice` or a nonempty diagnosed `no-voice`, never silently return void. These are required ports, not timers, synthetic sounds or silent fallbacks. This leaf exports no sound assets and changes no audio transport. Every asynchronous port must stop writes and settle on abort; the host drains the sound finalizer before VM recovery.
7. Preserve source-action recovery snapshots of State, actor logical/tween/animation ownership and orbit. Recovery drains the VM port before rehydrating the field. Unload calls `host.leave` before changing field ownership; World.beginFieldTransition does this before shared task cancellation.

Actual Main/audio bindings, visual/interactive checks and production integration are outside this leaf and require fresh review of those exact bytes. Existing renderer/clock reviews do not transfer automatically.
